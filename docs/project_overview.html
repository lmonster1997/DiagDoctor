DiagDoctor — 项目架构与实现速览

一个 LLM 驱动的 Web 应用 Bug 诊断 Agent:给定出错应用(demo-app/TaskFlow)的错误现象 + 日志/trace,编排工具定位根因并给修复建议,由 Langfuse 评测。

基于源码逐文件核对 · 2026-08-01 · doctor 后端为主 · 末尾含已定位 Bug 嫌疑清单(供修复用)

1. 项目概览

DiagDoctor 由三个子系统组成。其中 doctor 是诊断 Agent 主体(本介绍重点),demo-app 是被诊断的靶应用(也是可观测信号的来源),bug-factory 量产可复现评测 case。

doctor 主图(实际):3 节点 bug_info → diagnosis_agent → human_input(HITL) → END;diagnosis agent 用 LangChain create_agent() + 7 个 middleware 管线(注意:非手写 while 循环,Iteration 3 从手写循环迁移而来,借 middleware 找回预算/去重/forced-call 注入点)。状态为 typed DoctorState(TypedDict,声明的 add reducer 真跑);checkpointer 为持久 _LazyAsyncSqliteSaver(data/checkpoints.db),支持 HITL 跨重启恢复。

技术栈:Python · FastAPI · LangGraph · LangChain 1.0(middleware API) · Pydantic · structlog · OpenTelemetry · Langfuse · Qdrant · psycopg3。

17. 一次诊断的完整旅程(端到端)

用户在 doctor/frontend 聊天框描述 bug(或 REST POST /api/diagnose)
  │
  ▼ bug_info_node (bug_info.py:193)
  ├─ CopilotKit: LLM 提取 BugInfo(user_report/trigger_time/trace_ids)
  ├─ set_trigger_time -> search_observability 用 trigger_time ±5min
  ├─ _prefetch_service / _prefetch_by_trace_ids -> Loki/Tempo 预取
  ├─ ingest(raw) -> NormalizedEvidence(golden_signals, correlations)
  └─ case_id = thread_id(与 checkpointer 寻址同 key)
       │
       ▼ diagnosis_agent_node (diagnosis_agent.py:179)
  ├─ format_evidence_for_agent -> evidence_text
  ├─ RAG: search_historical_cases -> §6.5 注入块(首次查询+缓存)
  ├─ set_run_context(DiagnosisRunContext)
  ├─ agent.ainvoke({messages:[System, RAG?, Human(evidence)]}, recursion_limit=200)
  │    │
  │    ▼ create_agent ReAct 循环(7 middleware 钩入)
  │    ├─ [abefore_agent] Lifecycle 初始化 budget; Langfuse start_trace
  │    ├─ 每轮 [abefore_model] ContextElision ageing -> BudgetGuard 检查
  │    ├─ model call(诊断 LLM)
  │    ├─ [aafter_model] BudgetGuard 记 real usage + record_hypothesis 豁免
  │    ├─ [awrap_tool_call] Dedup -> Langfuse span -> Truncation -> 工具 -> BudgetGuard 计数
  │    └─ natural stop 或 BudgetGuard jump_to:"end"
  │    │
  │    ▼ [aafter_agent] ForcedFinalCall: 无 JSON -> 强制再调一次
  ├─ _finalize_report: parse_diagnosis_report + extract_findings + clamp_referenced_case_ids
  └─ langfuse end_trace(report)
       │
       ▼ _route_after_diagnosis
  ├─ early_stopped & !hitl_resumed -> human_input(interrupt,checkpoint 持久化)
  │    └─ resume Command(resume=guidance) -> diagnosis_agent 第二轮(scratchpad 续查)
  └─ else -> END -> report 流回前端 ReportPanel / REST response

— 本文档由源码逐文件核对生成。evidence(/§11) 与 memory(/§12) 两节因最后一处代码复核仍在进行,基于状态模型+现状文档+配置整理,已标注;其余章节均直接基于源码。Bug 嫌疑清单供后续修复排期。
